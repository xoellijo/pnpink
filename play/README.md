# PnPPlay

`PnPPlay` turns a declarative game package into a playable browser table.
The package describes pieces, areas, initial setup, visibility, layout, and
the generic operations players may perform. No game-specific TypeScript is
required for sandbox-style prototypes.

## Immediate Play

After generating a deck, the **Play** button in Deckmaker exports every item as
a 150 dpi PNG, writes a `<template>.play` package beside the SVG, starts the
local Python server, creates a persistent room, and opens it in the browser.
The first table preset is optimized for four-player trick-taking prototypes. It
deals private hands, keeps the current viewer at the bottom, places opponents
around the table and supports playing cards by click or Boardzilla dragging them.

The player runtime uses Inkscape's Python and prebuilt JavaScript bundles, so
normal users do not need Node.js or npm. Runtime packaging and installation are
intentionally kept separate until the required feature set is stable.

## Development

```bash
npm install
npm run typecheck
npm test
npm run build
```

The included `play.yaml` is the designer-facing configuration. `play.json`
is the equivalent normalized interchange format generated by PnPInk.

## Manifest

Every package contains `play.yaml` or `play.json` and its referenced image
files. YAML may contain comments and describes players, turn assistance,
areas, pieces and setup without becoming a rules language.

```yaml
players:
  count: 4

turns:
  mode: trick-assisted
  order: right
  maxCardsPerPlay: 1
  winnerDecider: last

setup:
  - shuffle: deck
  - deal: {from: deck, to: hand, count: 13}
```

PnPInk item exports can remain in their own compact JSON file. The manifest
links the complete deck and chooses its initial area without listing every card:

```yaml
pieces:
  source: assets/items.json
  initial: {area: deck}
  extra:
    - {id: red-token, label: Red token, type: token, color: '#d94b4b', initial: {area: tokens}}
```

`extra` keeps reusable resources beside a linked card dataset without expanding
the deck in YAML. Image paths inside `items.json` are relative to that file. See
`examples/poker/play.yaml` for a complete 52-card example.

`trick-assisted` advances after each played card, pauses after every player has
played, and asks who takes the trick. The selected winner receives the cards
and leads next. It deliberately does not validate suits, trump or winners.

`order` accepts `right` (the default/current order) or `left` and controls which
seat plays next. `maxCardsPerPlay` is the maximum group played as one atomic
move; it defaults to `1`, accepts any positive integer, and `0` removes the
limit for games such as Tichu. The destination area's `maxDrop` still applies.

`winnerDecider` controls who may choose the trick winner: `last` (default),
`next-to-last`, `host`, or `all`. With `all`, any player may resolve the trick;
it does not introduce voting or require every player to confirm the result.

Coordinates are percentages of the game canvas. Player areas may define
different rectangles for their owner and their opponents, so every player sees
their own area in the preferred position.

Set `maxDrop` on an area to limit how many selected pieces it accepts in one
operation. For example, `maxDrop: 1` keeps a table slot single-card while a
discard pile without that property accepts an entire selection.

Player areas may also define `canHide: toggle`, `sync`, or `select`. `toggle`
lets each owner hide or show their area, `sync` keeps every matching player
area hidden until all owners reveal theirs, and `select` lets the owner choose
which players can see it. Hidden contents use Boardzilla's native view
screening, so other clients receive neither the pieces nor their count.

Optional `toolboxes` place shared or player-owned trays outside the felt. An
area joins one with `toolbox: toolbox-id`; `kind: supply` makes it a stack-like
bowl, and `infinite: true` replenishes every component removed from it. Pieces
accept `type: card`, `token`, `chip`, or `d6`, plus optional `color`, `value`, and
`shape: circle|square` for compact resources. Dice use Boardzilla's native animated `D6` component.
Dropping a resource on its toolbox returns it to the matching supply declared
by its initial area. Toolboxes are omitted entirely when the manifest does not
define them.

```yaml
toolboxes:
  - {id: general-tools, label: General tools, scope: shared, side: left}
areas:
  - id: red-tokens
    label: Red tokens
    kind: supply
    scope: shared
    visibility: public
    toolbox: general-tools
    infinite: true
    actions: [move-from, move-to]
    layout: {rows: 1, columns: 1}
pieces:
  - {id: red-token, label: Red token, type: token, color: '#d94b4b', copies: 6, initial: {area: red-tokens}}
```

The runtime intentionally contains only universal tabletop operations. Rules,
validation, scoring, and automation can later be layered on top without
changing the piece or setup format.

Cards and stacks expose compact `lil-xgui` context menus through right-click or
long-press. Drag on empty table space to draw a selection rectangle, use
`Ctrl`/`Cmd`-click to add or remove cards, and press `Esc` or click outside to
clear the selection. Dragging any selected card moves the group through the
same validated Boardzilla action and destination highlighting as a single card.
